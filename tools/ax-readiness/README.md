# AX 전환 준비도 진단: 설계 근거와 응답 저장소 연결

페이지: `in-progress/ax-readiness/index.html` · 스크립트: `assets/js/ax-readiness.js` · 저장소: `apps-script.gs`

## 1. 무엇을 재는가

**AX(AI 전환)** 는 AI 도구를 들여오는 데서 끝나지 않고, 사람이 일하는 방식부터 회사의 업무 체계까지 AI를 전제로 다시 짜는 일이다. 이 도구는 그 전환을 받아들일 **준비 조건이 지금 어디까지 갖추어졌는지**를 구성원의 응답으로 진단한다.

- 성숙도(지금 AI를 얼마나 쓰고 있나)가 아니라 **준비도(전환을 해낼 조건이 갖추어졌나)** 를 잰다. 개인 사용은 거의 보편화되었는데 조직은 시범 단계에 머무는 "개인 도입–조직 성숙 격차"가 반복해서 보고되기 때문이다([E-mentor, 2026](https://www.e-mentor.edu.pl/eng/article/index/number/114/id/1752)).
- 기술보다 사람과 업무 방식이 더 큰 몫을 차지한다. BCG는 AI 가치의 70%가 업무 프로세스와 일하는 방식의 변화에서 나온다고 본다([BCG 10-20-70](https://bcg.com/publications/2022/5-rules-for-fixing-ai-and-machine-learning-for-your-business)).

## 2. 다섯 단계

| 단계 | 문항 주어 | 핵심 질문 | 주된 근거 |
| --- | --- | --- | --- |
| 1. 개인 준비 | 나는 | 나는 AI와 일할 준비가 되었나? | 개인 변화 준비도: 효능감·개인 효용 ([Holt 외, 2007](https://nccmt.ca/resources/search/226)) |
| 2. 직무 재설계 | 내 직무에서는 | 내 일은 AI를 전제로 다시 짜였나? | 디지털 시대의 일 설계 ([Parker & Grote, 2022](https://folia.unifr.ch/global/documents/66793)) |
| 3. 팀 협업 | 우리 팀은 | 우리 팀은 AI와 함께 일하는 방식이 있나? | 집단 수준 변화 준비도 ([Rafferty 외, 2013](https://research-repository.griffith.edu.au/items/35eb1b1c-efe2-416d-8cb3-eca6f1fbaaeb)) |
| 4. 조직 기반 | 우리 회사는 | 회사는 AX를 이끌 체계를 갖췄나? | 조직 AI 준비 요인: 전략 정렬·자원·지식·문화 ([Jöhnk 외, 2021](https://aisel.aisnet.org/bise/vol63/iss1/2)), Cisco AI 준비 지수의 전략·거버넌스·인재·문화 ([Cisco, 2025](https://www.rcrwireless.com/20251209/ai/cisco-ai-readiness-index-2025)) |
| 5. 전사 시스템 | 우리 회사의 업무 체계는 | AI가 회사의 업무 체계에 녹아들었나? | 기업 AI 성숙도 3~4단계 ([MIT CISR, 2024](https://cisr.mit.edu/sites/default/files/2024-12/EnterpriseAIMaturityModel_CISRpressrelease_121924_0.pdf)), 에이전트가 프로세스를 운영하는 프런티어 기업 ([Microsoft, 2025](https://microsoft.com/en-us/worklab/work-trend-index/2025-the-year-the-frontier-firm-is-born)) |

**왜 다섯 단계인가.** 단계를 줄이면 서로 다른 책임 주체가 한 점수에 섞인다. 개인 준비(구성원)와 직무 재설계(구성원+리더)를 합치면 "사람은 준비됐는데 일이 그대로인" 흔한 병목이 보이지 않고, 조직 기반(경영진)과 전사 시스템(전사·IT)을 합치면 "제도는 있는데 데이터와 시스템이 따로 노는" 병목이 보이지 않는다. 단계마다 고칠 사람이 다르므로 다섯 단계로 나눴다.

**왜 이 순서인가.** 앞 단계가 다음 단계의 전제라는 가설이다. 사람이 준비되어야 직무를 다시 짤 수 있고, 직무가 바뀌어야 팀의 일하는 방식이 바뀌며, 팀의 실천이 쌓여야 회사의 제도가 실제로 작동하고, 그 위에서 부서를 넘는 시스템 통합이 가능하다. 다만 실제로는 경영진이 지침이나 데이터 기반을 먼저 마련하는 경우도 있다. 그래서 순서는 **검증할 가설**로 두고, 회사 결과 화면에 "단계 순서 일치율"을 표시한다(5절).

## 3. 문항 (27문항)

응답: 1 전혀 그렇지 않다 ~ 5 매우 그렇다. 4~5단계와 전반 인식 문항에는 "잘 모르겠다"(0)를 둔다.

| 코드 | 문항 | 측면 |
| --- | --- | --- |
| P1 | 나는 업무에 쓸 수 있는 AI 도구의 기본 기능을 익혔다. | 기본 숙련 |
| P2 | 나는 내 업무 가운데 AI를 정기적으로 활용하는 일이 있다. | 사용 경험 |
| P3 | 나는 AI가 내 업무에 어떤 도움이 되는지 구체적인 예를 들 수 있다. | 개인 효용 인식 |
| P4 | 나는 AI 도입으로 내 업무 방식이 바뀌는 것을 받아들일 마음이 있다. | 변화 수용 |
| P5 | 나는 AI 활용 능력을 키우려고 스스로 시간을 내어 배우고 있다. | 자기 학습 |
| J1 | 내 업무 가운데 AI에게 맡길 과업이 구체적으로 정해져 있다. | 과업 구분 |
| J2 | 내 업무에서 AI 결과를 사람이 확인해야 하는 단계가 정해져 있다. | 사람 판단 지점 |
| J3 | AI 도입에 맞추어 내 역할(맡는 일의 범위)이 다시 정해졌다. | 역할 재정의 |
| J4 | 내가 받는 업무 목표에 AI 활용이 반영되어 있다. | 목표 반영 |
| J5 | 내 업무에 맞는 AI 도구를 회사가 허용한 범위 안에서 바로 쓸 수 있다. | 도구 접근 |
| T1 | 우리 팀의 업무 절차에는 AI를 쓰는 단계가 정해져 있다. | 절차 통합 |
| T2 | 우리 팀원들은 AI 활용 노하우를 서로 공유한다. | 지식 공유 |
| T3 | 우리 팀은 AI를 새로 시도하다 생긴 실패를 배움의 기회로 다룬다. | 심리적 안전 |
| T4 | 우리 팀의 리더는 팀원들이 AI 활용을 시도하도록 지원한다. | 리더 지원 |
| T5 | 우리 팀은 AI를 쓸 때 지킬 기준(예: 입력하면 안 되는 정보, 검토 절차)을 정해 두었다. | 팀 규범 |
| O1 | 우리 회사는 AX로 이루려는 목표를 구성원에게 분명히 알렸다. | 전략·소통 |
| O2 | 우리 회사 경영진은 AX 추진에 필요한 자원(예: 예산, 인력)을 배정하고 있다. | 경영진 투자 |
| O3 | 우리 회사는 AI 사용에 관한 공식 지침(예: 보안, 개인정보, 책임 범위)을 갖추고 있다. | 거버넌스 |
| O4 | 우리 회사는 직무에 맞는 AI 교육 기회를 제공한다. | 인재 육성 |
| O5 | 우리 회사는 AI 활용으로 성과를 낸 구성원을 공식적으로 인정한다. | 인정 제도 |
| S1 | 우리 회사의 업무 데이터는 부서 구분 없이 AI가 활용할 수 있도록 연결되어 있다. | 데이터 연결 |
| S2 | 우리 회사의 핵심 업무 시스템(예: ERP, 그룹웨어)에는 AI 기능이 연동되어 있다. | 시스템 연동 |
| S3 | 우리 회사는 여러 부서에 걸친 업무 프로세스를 AI 활용을 전제로 다시 설계했다. | 전사 프로세스 재설계 |
| S4 | 우리 회사는 AI가 만든 성과(예: 절감된 시간, 비용, 품질 개선)를 전사 차원에서 측정한다. | 가치 측정 |
| S5 | 우리 회사에서는 AI가 사람의 감독 아래 업무 프로세스의 일부 단계를 직접 처리한다. | 감독 하 자동 처리 |
| G1 | 우리 회사 구성원들은 AX 전환을 해내려는 의지가 강하다. | 변화 몰입 (준거) |
| G2 | 우리 회사는 AX 전환을 해낼 역량을 갖추고 있다. | 변화 효능감 (준거) |

G1·G2는 단계 점수에 넣지 않는다. Weiner의 조직 변화 준비도 정의(변화 몰입 + 변화 효능감)를 그대로 묻는 준거 문항으로, 다섯 단계 점수가 이 전반 인식을 설명하는지 확인하는 데 쓴다([Weiner, 2009](https://link.springer.com/article/10.1186/1748-5908-4-67)).

## 4. 설계 원칙

1. **한 단계 안에서는 주어를 통일한다.** 1단계는 "나는", 2단계는 "내 직무", 3단계는 "우리 팀", 4~5단계는 "우리 회사". 집단 수준 준비도는 "나"가 아니라 집단을 주어로 묻는 문항(참조 대상 이동)이 권장되며([Weiner, 2009](https://link.springer.com/article/10.1186/1748-5908-4-67)), 성과 관련 결과를 예측할 때 집단 참조 문항이 더 강했다([Wallace 외, 2016](https://mikechristian.web.unc.edu/wp-content/uploads/sites/13307/2016/11/Wallace-et-al-Change-the-Referent-Journal-of-Management-2016.pdf)). 쪽마다 한 단계씩 제시해 주어가 바뀌는 지점을 분명히 했다.
2. **모든 문항은 "지금 갖추어진 상태"를 기술한다.** 계획·의도("~할 것이다")나 당위("~해야 한다")는 쓰지 않는다.
3. **한 문항은 하나만 묻는다.** "와/과·및"으로 두 대상을 잇지 않는다. 괄호 예시는 같은 범주 안에서만 든다.
4. **회사 수준 문항에는 "잘 모르겠다"를 둔다.** 구성원이 알기 어려운 내용을 짐작으로 답하면 중간값이 부풀고 평균이 왜곡된다. "모르겠다"는 점수에서 빼되 비율을 따로 보고한다. 모르는 사람이 많다는 것 자체가 소통 부족의 신호다.
5. **부정문·절대어·전문용어를 쓰지 않는다.** "에이전트"는 "사람의 감독 아래 업무의 일부 단계를 직접 처리하는 AI"로 풀어 썼다.

## 5. 채점과 해석

| 점수 | 산출 |
| --- | --- |
| 단계 점수 (0~100) | 응답한 문항 평균(1~5)에서 1을 빼고 25를 곱함. "모르겠다" 제외, 5문항 중 4문항 이상 응답해야 산출(아니면 판단 보류) |
| 준비된 단계 (0~5) | 1단계부터 차례로 기준점 60점 이상인 단계까지. 중간에 미달 단계가 있으면 거기서 멈춤(비보상 누적 규칙) |
| 병목 단계 | 처음으로 60점에 못 미친 단계 |
| 회사 단계 | 응답자 단계 점수의 평균으로 위 규칙 적용 |
| 합의도 rwg(j) | 4·5단계(회사 참조 문항)의 구성원 간 합의. 균등분포 기대분산 2 기준. .70 이상이면 평균을 회사 상태로 해석 |
| 단계 순서 일치율 | 다섯 단계 점수가 모두 있는 응답자 중, 앞 단계를 넘지 못했는데 뒤 단계를 넘은 사례가 없는 비율 |

**측정 모형에 관한 주의.** 단계 문항은 같은 특성을 반복해서 재는 반영 지표라기보다, 함께 모여 준비 상태를 이루는 **조건 목록(형성 지표)** 에 가깝다. 예를 들어 "공식 지침이 있다"와 "성과를 인정한다"는 서로 상관이 낮아도 둘 다 조직 기반의 구성 요소다. 따라서 결과 화면의 신뢰도 α는 참고용이며, α가 낮다고 문항을 지우지 않는다. 타당성은 내용 대표성(전문가 검토)과 외적 준거(G1·G2, 실제 AX 성과)로 확인한다.

## 6. 타당화 계획 (배포 전후)

1. **내용타당도**: HRD·조직개발·IT 전문가 6~10인이 문항별 관련성(4점)과 단계 배치를 평정. I-CVI .78 미만 문항 수정.
2. **인지면담**: 직급별 2~3명씩. 특히 J3(역할 재정의), S3(전사 프로세스 재설계), S5(감독 하 자동 처리)를 어떻게 이해하는지 확인.
3. **예비 적용**: 한 회사에서 50명 이상. "모르겠다" 비율, 바닥·천장 효과(최저·최고점 응답 15% 초과), 응답 시간 확인.
4. **단계 순서 검증**: 여러 회사 자료로 누적 척도 분석(Guttman 재현성, Mokken 척도 분석)을 해서 "개인 → 전사 시스템" 순서가 성립하는지 확인. 성립하지 않으면 누적 규칙 대신 단계별 프로필만 보고.
5. **집계 타당성**: 회사(부서) 단위로 rwg(j), ICC(1), ICC(2)를 보고하고, 부서별 차이가 크면 부서 단위 결과로 해석.
6. **준거타당도**: 단계 점수가 G1·G2, 그리고 6개월 뒤의 객관 지표(AI 활용 과제의 운영 전환 수, 업무 시간 절감 등)를 예측하는지 확인.
7. **기준점 설정**: 잠정 기준점 60점은 전문가 판정과 준거 자료로 다시 정함.

## 7. 응답 저장소 연결 (5분)

`endpoint`가 비어 있으면 **시험 모드**로 동작한다. 응답은 응답자 브라우저(localStorage)에만 저장되고, 그 브라우저의 응답끼리만 분석한다. 실제로 응답을 모으려면 AI 역량 진단과 **다른** 스프레드시트에 연결한다(문항 구성이 다르다).

1. 개인 Gmail 계정으로 새 스프레드시트를 만든다. 이름 예: `AX 준비도 진단 응답`.
2. **확장 프로그램 → Apps Script**를 열고, 기본 코드를 지운 뒤 `apps-script.gs` 내용을 붙여 넣고 저장한다.
3. **배포 → 새 배포 → 유형: 웹 앱**, 실행 계정 **나**, 액세스 권한 **모든 사용자**.
4. 권한을 승인하고 나오는 웹 앱 URL을 `in-progress/ax-readiness/index.html` 머리말에 넣는다.
   ```yaml
   endpoint: "https://script.google.com/macros/s/…/exec"
   ```

응답은 `responses` 시트에 한 줄씩 쌓인다(제출 시각, 결과 코드, 그룹, 구분, 응답 시간(초), 27문항). "잘 모르겠다"는 0으로 저장된다.

## 8. 회사별로 받기

링크 뒤에 `?group=회사코드`를 붙이면 그 링크로 들어온 응답만 모아 "우리 회사 분석결과"를 계산한다.

- 예: `https://hrdpro.hanyang.ac.kr/in-progress/ax-readiness/?group=ACME2026`
- 부서별로 따로 보고 싶으면 `?group=ACME-영업`처럼 부서를 붙인 코드를 쓴다. 다만 인원이 적은 부서는 응답자가 드러날 수 있으므로 5명 이상일 때만 쓴다.
- 응답자 구분별 비교는 각 구분이 3명 이상일 때만 표시한다.

## 9. 알아 둘 점

- 웹 앱은 그룹 응답 목록을 누구에게나 돌려준다(결과 코드는 빠지고, 구분과 27개 응답값만). 이름·이메일·부서는 묻지 않는다.
- 저장 키 판(`axr-v1`)을 올리면 응답자 브라우저에 남은 예전 결과가 무시된다.
- 준비 기준점 60점, 단계 순서, 해석 문구는 타당화 전의 잠정 기준이다. 자료가 모이면 `ax-readiness.js`의 `CUT`, `STAGE_DESC`, `ACTIONS`를 조정한다.
