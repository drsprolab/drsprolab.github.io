# AI Agent 요구도 분석: 응답 저장소 연결

페이지 `in-progress/ai-agent-needs/index.html` · 스크립트 `assets/js/ai-agent-needs.js` · 문항 `assets/data/ai-agent-needs.json` · 저장소 `apps-script.gs`

1. 새 Google 스프레드시트 → 확장 프로그램 → Apps Script → `apps-script.gs` 내용을 붙여 넣고 저장
2. 배포 → 새 배포 → 유형 "웹 앱", 실행 계정 "나", 액세스 "모든 사용자" → 배포
3. 웹 앱 URL(`https://script.google.com/macros/s/.../exec`)을 페이지 front matter의 `endpoint:`에 넣는다. 비워 두면 시험 모드(이 브라우저에만 저장)
4. 코드를 고친 뒤에는 배포 관리 → 수정 → 새 버전으로 다시 배포한다(URL 유지)

시트 `responses`: 제출 시각, 결과 코드, 그룹(?group=), 배경 5문항, 심화 여부, 소요 시간, `I_A01…I_G03`(중요도), `P_A01…P_G03`(수행수준). 심화 문항은 심화 응답자만 채운다.

분석(브라우저에서 계산): 문항별 중요도·수행수준 평균, 대응표본 t 검정, Borich 요구도(= (I−P) 평균 × I 평균), Locus for Focus·IPA 사분면, 최우선(= Borich 상위 K위 ∩ LFF HH, K = HH 문항 수)·차우선.

## 결과 화면의 두 분석 수준

- 상위 요약은 기존 7개 영역(A~G)을 유지한다. 교육 내용의 묶음이며 통계적 군집분석 결과가 아니다.
- 결과용 세부 기술명은 데이터 JSON의 `skill_labels`에 정의한다. 예: 검색 도구 활용, 핵심정보 확인, 참고자료 실재 확인. 원문 문항과 저장 코드는 유지한다.
- 영역 점수는 해당 영역의 세 기술 모두에 중요도·수행수준을 응답한 학생의 차원별 평균으로 산출한다. 영역 Borich는 학생별 영역 평균으로 구한 전체 평균차 × 전체 평균 중요도다. 문항별 Borich 평균과는 다른 지표다.
- 공통 5개 영역과 심화 2개 영역은 각각 순위와 IPA·LFF 평균 기준선을 산출한다. 영역 점수는 교육 내용을 비교하기 위한 기술통계다.
- 영역 상세 분석은 해당 영역의 세부 기술마다 동일 응답자 쌍으로 Borich와 대응표본 t·p를 산출한다. 해당 영역 기술만으로 순위와 IPA·LFF 평균 기준선을 다시 계산한다. 영역 내부 상대적 분류이며 영역 간 직접 순위로 해석하지 않는다.
- Borich 상위 K위(K는 LFF HH 개수)와 LFF HH가 겹치고 차이가 양수인 기술·영역을 우선 후보로 표시한다. Borich 동률은 원래 기술 순서로 표시 순위를 정한다.
- 전체 결과는 기술·영역별 5명 이상, 구분별 비교는 3명 이상만 표시한다. 그룹 전체 인원이 충분하더라도 심화 유효 응답이 부족하면 해당 칸은 분석 대기다.
- 전체 7개 영역을 선택하면 모든 영역의 Borich·IPA·LFF와 세부 지표를 함께 확인하고 PDF로 저장할 수 있다. PDF는 현재 탭과 선택한 범위를 반영한다.

### 교육과정 수립 제언
현재 결과 필터의 응답을 사용하여 공통·심화별 양의 영역 차이를 갖는 영역을 Borich 내림차순으로 편성한다. 동점은 기존 영역 순서다. 각 단계에서는 유효 응답 5명 이상·양의 차이를 가진 세부 기술을 Borich순으로 안내하고 구체적 지도 내용과 실습 결과물을 제시한다. IPA/LFF는 보조 근거로 병기한다. 선수학습 안내는 통계 순위와 구분하며, 실제 수행 확인 후 수업 순서를 조정한다. 음의 차이·0 차이는 집중 과정에서 제외하고 응답 부족은 보류한다.
